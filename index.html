Cloud Architecture & Governance Specification

MFC Youth Area Management System (AMS)

Cloud-based pastoral operations and community governance platform engineered for Missionary Families for Christ (MFC) Youth.

1. Architectural Stack 3-Tier Cloud

┌────────────────────────────────────────────────────────┐
│               Client Application (PWA)                 │
│         React 19 • TypeScript • Vite • Zustand         │
│          Tailwind CSS • Lucide Icons • TanStack        │
└───────────────────────────┬────────────────────────────┘
                            │ HTTPS / JSON REST
                            ▼
┌────────────────────────────────────────────────────────┐
│            Vercel Serverless Functions API             │

│       Micro-handlers: auth, members, events, areas     │
└───────────────────────────┬────────────────────────────┘
                            │ PostgreSQL Wire / Service Role
                            ▼
┌────────────────────────────────────────────────────────┐
│                 Supabase Cloud Database                │
│    PostgreSQL • Row Level Security (RLS) on all tables │
│        Auth Service • Encrypted Session Management     │
└────────────────────────────────────────────────────────┘
Frontend Tier

frontend-react/ (PWA)

Single-Page Progressive Web App with fast client-side routing, offline readiness, role-based view guards, and dark/light liturgical aesthetics. Built with React 19, TypeScript, Vite, Zustand, Tailwind CSS, TanStack Query, and Lucide Icons.

API Tier

Backend/ (Vercel Serverless)

Zero-cold-start Node.js micro-handlers grouped by domain (auth, members, chapters, events, services, gig, reports, dev) routed through a consolidated /api/router.js gateway.

Database Tier

Supabase Cloud Database

PostgreSQL tracked under Backend/supabase/ across 22 incremental SQL migrations. Employs Supabase Auth, encrypted session management, and strict Row Level Security across all 13 production tables.

2. 4-Tier Role-Based Access Control (RBAC) Scoped Governance

Tier 1 · Full Area Scope

Area Leadership

Comprehensive data visibility across the entire area for top-level coordinators and pastoral mentors.

  • National Coordinators
  • Area Servants
  • Couple Coordinators
Tier 2 · Ministry Scope

Domain Moderators

Ministry-specialized operational views partitioned by pastoral pillar:

  • LIT Servant: 5 Creative pillars (Music, Dance, Graphics, Writing, Production)
  • Campus Servant: College & Senior High School youth
  • MFC High Servant: Junior High School youth (Grades 7–10)
  • Area Kids Servant: Heartchamps transitioning into youth ministry
Tier 3 · Chapter Scope

Chapter Servants

Strictly scoped permissions for community chapter heads, managing chapter member rosters, event check-in, and submitting monthly assembly reports.

Tier 4 · Member Portal

Youth Members

Personal pastoral profile portal, gathering check-in confirmation, emergency contact maintenance, and daily liturgical readings.

3. Core Functional Modules Operations

Youth Member Roster & Pastoral Profiles

Tracks youth members (ages 13–21 and transitioning Heartchamps). Records emergency contacts, first youth camp attendance, active/inactive statuses, and academic tracks (College, Senior High, Junior High, Heartchamps).

Events & Gatherings

Manages youth camps, assemblies, conferences, and service meetings. Includes participant registration, multi-channel payment reconciliation (cash, GCash, bank), fee collection, and manual attendance check-in.

Activity Reports & Pastoral Audit

Standardized reporting pipeline where chapter servants submit assembly reports, participant attendance metrics, and pastoral reflections with area-wide audit visibility.

GIG (Give It Generously) Stewardship

Dedicated stewardship ledger logging financial offerings, pastoral support funds, and tithes with area-scoped accountability and transparent record-keeping.

Daily Scripture Readings

Automated Catholic liturgical daily mass readings feed integrated and dynamically displayed on both member dashboard and public login portals.

4. Security & Operational Hardening SecDevOps

Row Level Security (RLS)

Enforced on all 13 PostgreSQL tables (areas, chapters, members, events, reports, etc.) ensuring multi-tenant data segregation at the database engine level.

Rate Limiting & Brute Force Defense

Sliding window IP throttling via rate-limit.js and automatic temporary account lockouts after repeated failed attempts via brute-force.js.

Multi-Factor Authentication (MFA)

Built-in Time-based One-Time Password (TOTP) factor challenge and verification flows for administrative and pastoral servant accounts.

Global Admin Area Switching

National Coordinators and System Developers can switch active area contexts or simulate scoped roles without mutating underlying database records.
